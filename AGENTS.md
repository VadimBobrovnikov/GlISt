# AGENTS.md: Инструкции для ИИ-агента (Cline)

Этот файл содержит тактические правила для агента. Прочитай его перед началом любой задачи.

## Главные запреты (Critical Rules)
1. **НИКОГДА не изменяй тесты, чтобы они прошли.** Если тест падает — исправляй код, а не тест. Тесты пишутся ДО кода (TDD).
2. **НИКОГДА не хардкодь секреты.** Пароли и ключи берутся только из `os.environ` или `.env`. Файл `.env` не коммитится.
3. **НИКОГДА не выходи за рамки текущей задачи.** Если задача T013 требует создать модели — не пиши заодно API-эндпоинты.
4. **Геометрия — только PostGIS.** Запрещено вычислять площади или пересечения полигонов в Python (Shapely) — только SQL-функции PostGIS (Принцип IV Конституции).

## Окружение и терминал (Windows)
Проект разрабатывается на Windows. Из-за бага Flutter с кириллическими путями в папке проекта, используй следующие обходные пути:
- Всегда используй `uv` для Python. Запускай тесты так: `uv run pytest ...`, линтер: `uv run ruff check .`.
- Для любых команд Flutter/Dart переходи в ASCII-путь: `cd D:\glist\frontend` (это junction-ссылка на реальный проект).
- Если `flutter` не находится, используй явный путь: `D:\flutsdk\bin\flutter.bat analyze`.

## Архитектурные стандарты (Напоминание)
- Стек: FastAPI (Python 3.12), LangGraph, PostgreSQL 16 + PostGIS + pgvector.
- Агенты LangGraph (Researcher, Analyst, Visualizer, Validator) общаются ТОЛЬКО через общий State. Прямые вызовы между ними запрещены.
- Фронтенд (Flutter) обязан строго следовать макетам из `docs/prototypes/` и правилам из `docs/ui-design-system.md`.

## Процесс работы
1. Пиши тесты первыми (для бизнес-логики и инструментов). Покрытие не должно падать ниже 80%.
2. После написания кода прогоняй гейты: `ruff`, `mypy --strict`, `pytest`.
3. После завершения задачи делай `git commit` с сообщением `T<номер>: <описание>`.
4. Останавливайся после каждой задачи и жди подтверждения от пользователя ("Принято").
